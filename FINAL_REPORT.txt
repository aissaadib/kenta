============================================================

  to settings.json and is applied to the backend.

============================================================
3. FUNCTIONAL FIXES
============================================================
- Manual recording finalization (capture.rs): `stop_manual_recording` now
  concatenates the segments captured during the session into a validated
  MP4 in the output dir and returns the path; `start_manual_recording`
  records session start time so only session footage is included. Failures
  return real diagnostics; no fake success.
- Capture lifecycle ownership (lib.rs): Rust setup loads persisted settings,
  builds the CaptureEngine, and starts buffering automatically. Frontend no
  longer owns engine startup; navigation/rerenders cannot spawn duplicate
  FFmpeg processes.
- Hotkey invoke args (tauri.ts): `register_hotkeys` now sends camelCase
  `saveKey`/`recordKey`, eliminating the runtime "invalid args saveKey"
  banner.
- Audio toggles (App.tsx): mic/desktop-audio switches now call `setSettings`
  so changes persist and reach the backend.
- tauri.conf.json: `beforeDev`/`beforeBuild` separator `&&` -> `;`
  (Windows PowerShell compatibility).
- Commands added: `select_output_dir`, `rename_clip`, `list_clips`
  (search/sort params), `enumerate_audio_devices`,
  `enumerate_video_encoders`, `generate_thumbnail`, `open_in_player`.
- Capture engine uses selected mic/desktop-audio device instead of hardcoded
  `virtual-audio-capturer`.
