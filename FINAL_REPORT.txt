What the user can now do:
- Configure where clips are saved via a native folder picker (Browse) +
  Open Folder, instead of typing a Windows path.
- Search, sort (date/name/size/duration), and rename clips in the library,
  with real FFmpeg-generated thumbnails and an in-app video preview.
- Start manual recording and have it finalize into a validated MP4 clip
  registered in the library (previously returned "NotAvailable").
- Have the replay buffer start automatically from Rust application setup,
  independent of the React mount cycle.
- Choose real microphone/desktop-audio devices via dropdowns (enumerated
  from FFmpeg dshow), with toggles that actually persist.
- Use global hotkeys without the "invalid args saveKey" banner (invoke arg
  casing fixed to camelCase).
- See only encoders FFmpeg actually supports, with the active encoder
  displayed and unavailable ones marked.
- Capture a specific monitor via manual offset_x/offset_y inputs for gdigrab
  multi-monitor capture.

============================================================
3. FUNCTIONAL FIXES
============================================================
- Manual recording finalization (capture.rs): stop_manual_recording now
  concatenates session segments into a validated MP4; start_manual records
  session start time. Real diagnostics, no fake success.
- Capture lifecycle ownership (lib.rs): Rust setup loads settings, builds
  CaptureEngine, starts buffering automatically. No duplicate FFmpeg on
  frontend rerenders.
- Hotkey invoke args (tauri.ts): camelCase saveKey/recordKey, eliminating
  the "invalid args saveKey" banner.
- Audio toggles (App.tsx): mic/desktop-audio switches call setSettings and
  reach the backend.
- tauri.conf.json: `&&` -> `;` for Windows PowerShell compatibility.
- Commands added: select_output_dir, rename_clip, list_clips (search/sort),
  enumerate_audio_devices, enumerate_video_encoders, generate_thumbnail,
  open_in_player.
- Capture engine uses selected mic/desktop-audio device and monitor offset.
