============================================================
1. SUMMARY
============================================================
Continued the existing ClipVault (Tauri 2 + React 19 + Rust + FFmpeg +
SQLite) codebase without rewriting it. Fixed the highest-impact functional
defects and completed key workflows so the app behaves as its interface
promises.

What the user can now do:
- Configure where clips are saved using a native folder picker (Browse)
  instead of typing a path; open that folder from Settings.
- Search, sort (date/name/size/duration), and rename clips in the library.
- Start manual recording and have it actually finalize into a playable MP4
  clip that is registered in the library (previously returned "NotAvailable").
- Have the replay buffer start automatically from Rust application setup,
  independent of the React mount cycle.
- Persist microphone / desktop-audio toggle changes.
- Use global hotkeys without the "invalid args saveKey" banner (invoke arg
  casing fixed to camelCase).

============================================================
2. UX IMPROVEMENTS
============================================================
- Output directory: replaced free-text input with current-path display +
  native Browse button + Open Folder button. No more manual Windows path
  typing.
- Clip library: added search input, sort dropdown (Date/Name/Size/Duration),
  inline rename (Save/Cancel), and an empty-state that distinguishes "no
  clips" from "no matches".
- Output dir no longer has a stray Apply button; Browse applies immediately
  and persists to settings.json.
- Settings use proper controls throughout: dropdowns for encoder/resolution/
  FPS, switches for audio toggles, key-cap buttons for shortcuts.

============================================================
3. FUNCTIONAL FIXES
============================================================
- Manual recording finalization (capture.rs): stop_manual_recording now
  concatenates the segments captured during the recording session into a
  validated MP4 in the output dir and returns the path. start_manual records
  the session start time so only footage recorded during the session is
  included. Failures return real diagnostics; no fake success.
- Capture lifecycle ownership (lib.rs): Rust setup loads persisted settings,
  builds the CaptureEngine, and starts buffering automatically. The frontend
  no longer owns engine startup; navigation/rerenders cannot spawn duplicate
  FFmpeg processes.
- Hotkey invoke args (tauri.ts): register_hotkeys now sends camelCase
  saveKey/recordKey, eliminating the runtime "invalid args saveKey" banner.
- Audio toggles (App.tsx): mic and desktop-audio switches now call
  setSettings so changes persist and reach the backend.
- tauri.conf.json: beforeDev/beforeBuild command separator changed `&&` ->
  `;` for Windows PowerShell compatibility.
- Commands registered: select_output_dir, rename_clip; list_clips now
  accepts search/sort params.
